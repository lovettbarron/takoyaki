## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline chip spacing |
| sm | 8px | Label-to-control gaps, list item inner padding |
| md | 16px | Default element spacing, sidebar item padding |
| lg | 24px | Section padding, card inner padding |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level top/bottom padding |

Exceptions: Sidebar nav items use 44px minimum touch/click target height (accessibility) even though 44 is not a multiple of 8. Achieved via `min-h-[44px]` with `py-[10px]` inner padding.

*Sources: 8-point grid default; touch target exception follows WCAG 2.5.5*

## Typography

All sizing in `rem` equivalent to pixel values below (base 16px). Monospace is the dominant type face — proportional used only where explicitly noted.

| Role | Family | Size | Weight | Line Height | Notes |
|------|--------|------|--------|-------------|-------|
| Body | Iosevka | 14px (0.875rem) | 400 regular | 1.6 | Primary reading size in lists, metadata, slot data |
| Label | Iosevka | 12px (0.75rem) | 500 medium | 1.4 | Nav labels, sidebar items, table headers, badges |
| Heading | Iosevka | 18px (1.125rem) | 600 semibold | 1.2 | Section headings within content area |
| Display | Iosevka | 24px (1.5rem) | 600 semibold | 1.1 | App title bar, major empty/disconnected state headings |
| Prose | Inter | 14px (0.875rem) | 400 regular | 1.6 | Confirmation dialogs, longer descriptive copy only |

**Weight contract:** Regular (400) and semibold (600) only. Medium (500) used only for label role. No other weights.

*Sources: CONTEXT.md D-08 (monospace-forward); Claude's Discretion (Iosevka selection, exact sizing)*

## Color

All values defined as CSS custom properties overriding shadcn defaults. Warm dark palette — slightly warm grays, not cool/blue-gray.

| Role | HSL Value | Hex Approx | Usage |
|------|-----------|-----------|-------|
| Dominant (60%) | hsl(30 8% 10%) | #1c1a18 | App background, base surface |
| Secondary (30%) | hsl(30 8% 16%) | #2a2723 | Sidebar, nav, cards, panel backgrounds |
| Elevated surface | hsl(30 8% 20%) | #332f2a | Hover states, active row, popover background |
| Foreground (primary) | hsl(30 10% 88%) | #e3ddd6 | Primary text — warm off-white |
| Foreground (muted) | hsl(30 8% 50%) | #8a8078 | Secondary text, metadata, disabled labels |
| Border | hsl(30 8% 26%) | #42403a | Dividers, input borders, card outlines |
| Accent (10%) | hsl(38 85% 55%) | #f0a832 | Reserved elements only (see below) |
| Accent foreground | hsl(0 0% 100%) | #ffffff | Text on accent backgrounds |
| Destructive | hsl(0 68% 48%) | #c73535 | Destructive actions only |
| Destructive foreground | hsl(0 0% 100%) | #ffffff | Text on destructive backgrounds |
| Connected indicator | hsl(140 60% 42%) | #29a85a | OT device connected status dot only |
| Disconnected indicator | hsl(30 8% 38%) | #66605a | OT device disconnected status dot only |

**Accent reserved for:**
- Volume detected / device connected confirmation button ("Use this device")
- Active/selected sidebar section indicator (left border or dot)
- Focus ring on interactive elements
- Link text within prose sections
- Primary CTA button background when device is connected

Accent is NOT used for: general hover states, data display, icons in default state, table row selection.

*Sources: CONTEXT.md D-06 (warm dark, off-white text, not pure black, not corporate muted); Claude's Discretion (specific hue/saturation values, accent color)*

## State Definitions

### Disconnected State (default on launch)

Content area shows:
```
[Display heading]  No Device Connected
[Prose body]       Connect your Octatrack in USB disk mode to get started.
                   The app will detect it automatically.
```

- No error icon, no red color — calm and neutral
- Sidebar sections for Backups and Settings remain accessible (pointer-events normal)
- Projects and Samples sections show the same "No Device" inline message if navigated to

### Device Detection Confirmation

Appears as a non-fullscreen dialog (shadcn `dialog`, not `alert-dialog`) — user can dismiss:
```
[Heading]    Octatrack Found
[Body]       Found a volume that looks like an Octatrack at:
             /Volumes/OT-CARD
             
             Would you like to use this device?
[Buttons]    [Use this device]  [Ignore]
```

- "Use this device" → accent button → auto-navigates to Projects view
- "Ignore" → ghost button → dialog closes, stays in disconnected state
- If multiple volumes detected: show volume name/path in a radio group within the dialog

### Connected State

- Titlebar shows device name with green indicator dot: `● OT-CARD`
- Sidebar "Projects" item shows active indicator (accent left border)
- Content area transitions to Projects view (Phase 2 builds content; Phase 1 shows skeleton)

### DB Init / Loading State

- Skeleton components fill the content area
- Sidebar items show skeleton label replacements
- Duration: typically <500ms — no loading screen needed, skeleton transitions are sufficient

*Sources: CONTEXT.md D-11, D-12, D-13, D-14*

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (volume detected) | "Use this device" |
| Primary CTA (dismiss volume) | "Ignore" |
| Disconnected heading | "No Device Connected" |
| Disconnected body | "Connect your Octatrack in USB disk mode to get started. The app will detect it automatically." |
| Device found heading | "Octatrack Found" |
| Device found body | "Found a volume that looks like an Octatrack at: {path}. Would you like to use this device?" |
| Volume removed toast | "Octatrack disconnected." |
| Volume connected toast | "Octatrack connected at {path}." |
| DB init error | "Could not initialize the database. Check that the app has write permission to its data directory." |
| Multiple volumes heading | "Multiple Devices Found" |
| Multiple volumes body | "Select the Octatrack volume to use:" |
| Disabled nav section (tooltip) | "Available in a future update" |
| Sidebar: Projects | "Projects" |
| Sidebar: Samples | "Samples" |
| Sidebar: Backups | "Backups" |
| Sidebar: Settings | "Settings" |

**Tone rules:**
- No ellipsis on loading states ("Loading…" → use skeleton instead)
- No exclamation points
- Hardware paths use monospace inline code formatting: `code` style
- Never say "error" in the volume detection flow — say "could not" or "unable to"

*Sources: CONTEXT.md D-11, D-12, D-13, D-14 (UX decisions); Claude's Discretion (exact copy)*

## Interaction Contract

| Interaction | Behavior |
|------------|---------|
| App launch | Disconnected state shown immediately; volume detection runs in background |
| OT volume mounted | Toast appears ("Octatrack connected…"); detection dialog appears after 500ms debounce |
| User confirms device | Dialog closes; sidebar Projects section activates; auto-navigate to Projects view |
| User ignores device | Dialog closes; disconnected state remains |
| OT volume unmounted | Toast appears ("Octatrack disconnected."); content area resets to disconnected state |
| Click disabled nav item | No navigation; cursor shows `not-allowed`; tooltip "Available in a future update" on hover |
| Keyboard focus | Visible focus ring using accent color; all interactive elements keyboard-reachable |

---

## Disabled State Contract

Sidebar sections for Samples, Backups, Settings in Phase 1:
- `opacity-50` on the nav item
- `cursor-not-allowed` 
- `pointer-events-none` (no click, no hover state)
- Tooltip via `title` attribute: "Available in a future update"
- Section icon present but muted (same icon, no special styling)
- No lock icon — design signal is opacity alone

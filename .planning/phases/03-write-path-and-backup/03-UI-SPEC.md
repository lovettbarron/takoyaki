**Weight contract:** Regular (400) and semibold (600) only. No exceptions.

**Phase 3 typography notes:**
- File sizes in snapshot entries use Body Iosevka with tabular nums: "128 MB", "42 files". Always include space before unit.
- Backup destination path uses Body Iosevka monospace, truncated with `text-ellipsis overflow-hidden whitespace-nowrap max-w-[320px]`
- Snapshot timestamps use Body Iosevka: "2026-04-30 14:32" — date + time, no seconds, no relative time ("2 hours ago" is NOT used)
- Operation labels in snapshot list ("manual backup", "pre-restore", "pre-rename") use Label weight, sentence case, no title case
- Change indicators in dry-run list ("Added", "Modified", "Removed", "Unchanged") use Label weight in their respective semantic color
- File counts in success banner use Body weight inline: "42 files · 128 MB"

## State Definitions

### Backups View States

**No backups yet (fresh install):**
```
No backups yet.
Back up a project from the Projects view to see it here.
```
Body Iosevka centered in content area. No icon.

**Disconnected device, backups exist:** Normal timeline view. [Restore] buttons visible but clicking them shows: "Connect your Octatrack to restore this snapshot."

**Backups loading:** Skeleton rows (2–3) in each project group.

**Backup running:** Progress view replaces content area in Backups section.

**Restore running:** Same progress view, label changes to "Restoring LIVESET_01…"

**Interrupted backup:** Banner at top of Backups view: "Backup incomplete. LIVESET_01 was not backed up. Try again." Destructive amber (Warning color) background variant (not red — this is a recoverable situation, not a data loss event).

**Interrupted restore:** Banner: "Restore aborted. LIVESET_01 is unchanged." Use Accent amber (Modified color) for this banner variant — the project is intact, this is informational.

### Dry-Run Modal States

**Loading file manifest (< 500ms typical):** Skeleton rows in file list. "Calculating changes…" in Label muted replaces operation summary.

**Manifest loaded:** Full file list rendered. Buttons become active.

**Operation in progress (after [Apply]):** Modal closes. Progress view takes over main content.

### Project List States (Phase 3 additions)

All Phase 2 project list states apply. Phase 3 adds:

**Project being backed up:** Project row shows an inline progress indicator (Lucide `Loader` spinning, 14px, muted) in the [Back Up] button column position while operation runs.

**Project last backed up (metadata):** No visible state change in project list — backup history visible only in Backups view. This keeps the project list clean.

## Interaction Contract

| Interaction | Behavior |
|-------------|---------|
| Click "Backups" in sidebar | Navigate to Backups view — accessible even when OT disconnected |
| Click [Back Up] on project row or in metadata header | Open dry-run preview modal for that project |
| Click [Cancel] in dry-run modal | Dismiss modal, no operation. Return to prior view state. |
| Click [Apply] / [Back Up N files] in dry-run modal | Close modal. Start backup. Show progress view in main content area. |
| Click [Restore This Snapshot] in snapshot detail | Open dry-run preview modal for that restore operation |
| Click [Apply] / [Restore Snapshot] in dry-run modal (destructive) | Close modal. Start restore. Show progress view. |
| Click snapshot row in timeline | Expand snapshot detail panel inline below that row. Collapse previously expanded row if any. |
| Click expanded snapshot row again | Collapse detail panel. Row returns to normal height. |
| Click [Restore] button in timeline row (not detail panel) | Shortcut: opens dry-run modal directly for that snapshot without needing to expand detail first. |
| Click [Cancel] during backup progress | Prompt: "Cancel the backup? No files have been written yet." [Keep Going] / [Cancel Backup]. |
| Click [Cancel] during restore progress | Prompt: "Cancel the restore? The project is unchanged." [Keep Going] / [Cancel Restore]. |
| Backup completes successfully | Progress view dissolves. Inline success banner appears for 4 seconds. Backups timeline updates to include new entry. |
| Restore completes successfully | Progress view dissolves. Success banner: "✓ Restored…". Backups timeline updated with pre-restore snapshot entry. |
| Backup fails (mid-operation) | Progress view shows error state. Banner: "Backup incomplete…" Warning amber variant. |
| Restore aborted by disconnect | Banner: "Restore aborted. LIVESET_01 is unchanged." Amber variant. |
| Click [✕] on success banner | Dismiss immediately. |
| Banner auto-dismiss (4s) | Slide-out-top animation. No user action required. |
| Keyboard Esc in dry-run modal | Same as clicking [Cancel] — dismiss modal, no operation. |
| Keyboard Enter in dry-run modal | No action — Enter does NOT trigger [Apply]. Prevents accidental confirmation. User must click [Apply] explicitly. |
| Focus within dry-run modal | Focus trapped inside modal. Tab cycles: Cancel → Apply → dismiss (✕) → file list (read-only) |
| Keyboard focus | Visible accent-color focus ring on all interactive elements: snapshot rows, [Restore] buttons, timeline rows |
| Tab key navigation | Sidebar → content area → snapshot rows (arrow keys within timeline) → detail panel → [Restore This Snapshot] → modal |

### Tone Rules (inherited + Phase 3 additions)

All Phase 1 and Phase 2 tone rules apply. Phase 3 adds:

- "Restore aborted. Project is unchanged." — always reassure the user that data is safe, even in error states
- Never say "overwrite" in the modal copy — say "restore" or "apply". Overwrite implies data loss; restore implies recovery.
- "A snapshot of the current state will be created before applying." — this exact phrasing appears verbatim in every dry-run modal, per CONTEXT.md D-10. Do not paraphrase it.
- Success banners use past tense ("Backed up", "Restored") — the operation is done.
- Progress headings use present continuous ("Backing up", "Restoring") — the operation is in progress.
- No ellipsis (...) in headings or buttons. Ellipsis allowed in progress heading only where grammatically required ("Backing up LIVESET_01…").
- File sizes: always include unit. "128 MB", not "128". "842 KB", not "0.82 MB".
- Timestamps in timeline: "2026-04-30 14:32" — no relative time, no "ago" language.
- Operation labels in timeline: lowercase ("manual backup", not "Manual Backup").

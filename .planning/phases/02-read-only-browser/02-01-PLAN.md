## Open Question Assumption Guards

The following assumptions are derived from RESEARCH.md Open Questions. Phase 1 clean-room spec work has NOT yet been completed, so these are best-effort assumptions with documented fallback strategies. Each assumption MUST be validated against Phase 1 fixtures when available.

**A2 - Tempo Encoding (Open Question 1):**
Assumed: OT stores tempo as integer x 10 (e.g., 1200 = 120.0 BPM).
Guard: The tempo conversion is isolated in a single constant `TEMPO_SCALE_FACTOR: f32 = 10.0` used in `index_ot_projects` and `get_project_detail`. If Phase 1 fixture data reveals a different scale factor, change this one constant.
Acceptance criteria: When a Phase 1 fixture with known tempo is available, verify that `raw_tempo / TEMPO_SCALE_FACTOR` equals the expected BPM value.

**A3 - Sample Path Encoding (Open Question 2):**
Assumed: OT sample paths are null-terminated, use backslash separators, and are relative to card root.
Guard: Path normalization is isolated in a single function `normalize_ot_path(raw: &[u8]) -> Option<String>` that handles: null termination (truncate at first 0x00), separator conversion (backslash to forward slash), leading separator stripping. If encoding differs, this function is the single point of change.
Acceptance criteria: When Phase 1 fixture data with known sample paths is available, verify that `normalize_ot_path(raw_bytes)` produces the expected path string.

**Open Question 3 - project.work vs project.strd:**
Decision: Read `.work` (autosave) for project index. Fall back to `.strd` if `.work` does not exist. This is the RESEARCH.md recommendation.

**Open Question 4 - Populated bank definition:**
Assumed: A bank is "populated" if its bank file can be parsed and contains at least one non-default pattern.
Guard: The `is_bank_populated()` function is isolated and can be adjusted. If the binary format has an explicit flag, use that instead. If not, any parseable bank file with non-zero content is treated as populated.
</assumptions>

#[tauri::command]
#[specta::specta]
pub async fn list_projects(
    state: tauri::State<'_, AppState>,
    filter: ProjectFilter,

    let db = state.db.lock().map_err(|e| AppError::Lock(e.to_string()))?;

2. **`get_project_detail`** -- Reads project.work + all 16 bank files via ot-parser. Returns a `ProjectDetail` struct containing: project_name, tempo_bpm (f32, divided by TEMPO_SCALE_FACTOR from raw value -- per assumption guard A2), bank_count, last_modified, and a `banks: Vec<BankDetail>` array of 16 entries. Each `PartDetail` has: part_index (0-3), part_name (Option<String>), tracks (Vec<TrackDetail> with 8 entries). Each `TrackDetail` has: track_index (0-7), machine_type (String -- "Flex", "Static", "Thru", "Neighbor", "Pickup"), sample_slot_index (Option<u8>), sample_filename (Option<String>). Per D-05, D-06, D-07.

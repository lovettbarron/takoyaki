<objective>
Build all Rust-side Tauri commands and SQLite query functions for browsing OT projects, banks, sample slots, and project metadata. This plan creates the backend data layer that the frontend consumes via IPC.

Purpose: The frontend cannot render any project data without these commands. Every browsing view (project list, bank grid, sample slots, metadata header) calls one of these commands. The project index population runs on card mount and powers the searchable/filterable project list.
Output: Four working Tauri commands (list_projects, get_project_detail, get_project_banks, get_project_samples) registered in the app, plus SQLite project indexing.
</objective>

Create `crates/takoyaki-app/src/commands/projects.rs` with these commands:

1. **`list_projects`** -- Tauri command that queries the SQLite project index. Per D-01 and D-02.
```rust
#[tauri::command]
#[specta::specta]
pub async fn list_projects(
    state: tauri::State<'_, AppState>,
    filter: ProjectFilter,
) -> Result<Vec<ProjectSummary>, AppError> {
    let db = state.db.lock().map_err(|e| AppError::Lock(e.to_string()))?;
    db::projects::list_projects(&db.conn, &filter).map_err(|e| AppError::Database(e.to_string()))
}
```

2. **`get_project_detail`** -- Reads project.work + all 16 bank files via ot-parser. Returns a `ProjectDetail` struct containing: project_name, tempo_bpm (f32, divided by 10 from raw value), bank_count, last_modified, and a `banks: Vec<BankDetail>` array of 16 entries. Each `BankDetail` has: bank_index (0-15), populated (bool), bank_name (Option<String>), parts (Vec<PartDetail> with 4 entries). Each `PartDetail` has: part_index (0-3), part_name (Option<String>), tracks (Vec<TrackDetail> with 8 entries). Each `TrackDetail` has: track_index (0-7), machine_type (String -- "Flex", "Static", "Thru", "Neighbor", "Pickup"), sample_slot_index (Option<u8>), sample_filename (Option<String>). Per D-05, D-06, D-07.

```rust
#[derive(Debug, serde::Serialize, specta::Type, Clone)]
pub struct ProjectDetail { ... }

#[derive(Debug, serde::Serialize, specta::Type, Clone)]
pub struct BankDetail { ... }

#[derive(Debug, serde::Serialize, specta::Type, Clone)]
pub struct PartDetail { ... }

#[derive(Debug, serde::Serialize, specta::Type, Clone)]
pub struct TrackDetail { ... }
```

3. **`get_project_banks`** -- Lightweight version of project detail returning only bank populated flags and pattern indicators. Returns `Vec<BankSummary>` with 16 entries, each having: bank_index, populated (bool), pattern_count (u8). Per D-05, D-06.

4. **`index_ot_projects`** -- Walks the SETS directory on the mounted OT volume, parses each project.work file to extract metadata, and upserts into the SQLite projects table. Called on volume mount. Reads volume_path from AppState. Clears existing projects first with `clear_projects()`, then walks SETS/{set_name}/{project_name}/project.work. Tempo is divided by 10 (raw u16 1200 becomes f32 120.0). Bank count is derived from counting non-empty bank files. Last modified comes from `project_dir.metadata()?.modified()`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Frontend -> Rust IPC | Filter parameters (name, bpm_min, bpm_max, modified_since) cross from untrusted frontend to backend |
| OT binary files -> Parser | Binary data from CF card is parsed by ot-parser |
| File system paths | Sample slot paths from OT binary files are used to construct filesystem paths |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | db/projects.rs list_projects() | mitigate | All filter values use parameterized queries via rusqlite params -- never string interpolation |
| T-02-02 | Tampering | commands/projects.rs index_ot_projects() | mitigate | volume_path comes from AppState (set by Phase 1 volume detection), not from frontend. Frontend does not supply paths. |
| T-02-03 | Information Disclosure | commands/samples.rs get_project_samples() | accept | Sample filenames are local data on a local desktop app with no network exposure. Low risk. |
| T-02-04 | Tampering | commands/projects.rs get_project_detail() | mitigate | project_id is an opaque UUID looked up in DB; backend resolves card_path from DB, not from frontend-supplied path |
</threat_model>
